# কঠোর নিয়ম — পণ্য বা দোকান যোগের আগে

যে কেউ (মানুষ বা AI এজেন্ট) এই প্রজেক্টে পণ্য, অফার বা দোকান যোগ করবে, কাজ শুরুর আগে এই ফাইল পুরো পড়বে। **একটা নিয়মও না মানলে কাজ ফিরিয়ে নেওয়া হবে।** ধাপে ধাপে কীভাবে করতে হয় সেটা [adding-products.md](adding-products.md)-এ; এখানে শুধু নিয়ম — ব্যতিক্রম নেই।

## পণ্য যোগের নিয়ম

1. **আসল দাম নিজের চোখে যাচাই করবে।** প্রতিটা দোকানের পাতায় ঢুকে দাম, স্টক আর ছবি দেখে আসবে। আন্দাজের দাম, অন্য সাইটের কপি-করা তালিকা, মুখস্থ বা AI-এর জেনারেট করা দাম — কোনোটাই চলবে না।
2. **মডেল-কোড না মিললে অফার নয়।** একই নামে ভিন্ন মডেল হয় (Baseus Adaman 22.5W ≠ Adaman 2 30W; Bipow 15W ≠ Bipow 20W)। PPADM20S, OPB-7103C — এমন কোড দুই পাতায় মিলিয়ে নিতে হবে। কোড না পেলে অফারটা বাদ, আর "সম্ভবত এটাই" বলে ঢোকানো যাবে না।
3. **অন্তত ৩টা existing দোকান, না হলে পণ্য নয়।** নিয়ম এই: পণ্যটা যেসব দোকানের তালিকায় আছে (workers/stores/index.ts) তাদের থেকে অন্তত ৩টা লাগবে। সব দোকান ইন-স্টকে থাকা জরুরি না — Stock out লিস্টিংও গণ্য হবে, তখন `inStock: false` আর পাতায় দেখা দাম দিয়ে। কিন্তু পাতায় দামই না থাকলে ("To be announced") সেই দোকানের অফার রাখা যাবে না।
4. **অফিসিয়াল দাম বাধ্যতামূলক, আর sanity মানতে হবে।** প্রতিটা ভার্সনে `officialPrice` দিতে হবে। যেকোনো অফারের দাম অফিসিয়াল দামের ৪০%-এর কম বা ২৫০%-এর বেশি হলে সেটা বাদ পড়বে — এটা ভুল লিস্টিং (কভার, গ্লাস, ভুল মডেল) বাছাইয়ের ফিল্টার।
5. **নামের নিয়ম ভাঙা যাবে না।** ব্র্যান্ড আলাদা ঘরে। মডেলে Pro, Max, Plus, Ultra, FE, 5G, সাইজ, চিপ — কিছুই বাদ দেবেন না; এগুলো দিয়েই মডেল চেনা হয়।
6. **স্পেস আর ছবি আসল হতে হবে।** `specsSource` হিসেবে Star Tech-এর স্পেক-টেবিলের পাতা দিন। ইমেজ দোকানের আসল CDN URL থেকে, সর্বোচ্চ ৫টা; নিজে বানানো বা অন্য পণ্যের ছবি কখনো না।
7. **condition সত্যি লিখবে।** দোকানের কনফিগ (workers/stores/index.ts) যা বলে সেটাই: Star Tech/Motion View/Gadget & Gear অফিসিয়াল, Apple Gadgets/Gadget Breeze/Sumash/Diamu আনঅফিসিয়াল। সন্দেহ হলে পাতার ওয়ারেন্টি-লেখা দেখে স্থির করবে, মনে মনে নয়।
8. **যাচাইয়ের গেট পার না হলে এগোনো যাবে না।** `npm run worker:check -- <ফিল্টার>` চালিয়ে "০টা সিঙ্ক হবে না" না আসা পর্যন্ত কোনো পরের ধাপ (specs/build/seed) নয়। একটা ✗ থাকলেও আগে সেটা সারাতে হবে।

## দোকান (সেলার) যোগের নিয়ম

1. **আগে robots.txt আর Terms of Use।** কোনোটাতেই আটকে থাকলে দোকান বাদ। ব্যতিক্রম চাওয়া যাবে শুধু দোকানের কাছেই — ইমেইল করে অনুমতি বা feed।
2. **bot protection ফাঁকি দেওয়ার কোড কখনো না।** stealth plugin, নকল fingerprint, residential proxy, CAPTCHA-ভাঙা — কিছুই না। দোকান আটকালে দোকান বাদ, এইটুকুই।
3. **worker নিজের পরিচয় দিয়ে যাবে।** নিজের user-agent ছাড়া ব্রাউজার নকল করা যাবে না।
4. **পার্সযোগ্য দাম লাগবেই।** JSON-LD, variation JSON বা পরিষ্কার markup না থাকলে (বা JS-rendered হলে) দোকান বাদ।
5. **workers/stores/index.ts-এই সব entry।** sitemap, parser, condition, sample URL — সব ওখানে; অন্য কোথাও hard-code করা যাবে না।
6. **এই দোকানগুলো স্থায়ীভাবে বাদ:** Daraz (ToS-এ সংগ্রহ নিষেধ), Ryans (Cloudflare challenge), TechLand (robots আটকে), Pickaboo (403), GadStyle (403), Facebook (নিষেধ)। নতুন করে চেষ্টা করা সময় নষ্ট।

## পাইপলাইন — ক্রম বদলানো যাবে না

```
data/catalog/<ক্যাটাগরি>.json  →  worker:check (০ মেলেনি)
→ catalog:specs  →  catalog:build
→ seed: npx supabase db query --linked -f supabase/seed.sql
→ build:data  →  npm run build
```

- seed কখনো `db push --include-seed` দিয়ে নয় — hash রেকর্ড হয়ে যেতে পারে অথচ SQL না চলতেই পারে।
- নতুন ক্যাটাগরি হলে `scripts/import-catalog.mjs`-এর `DEFAULT_CATEGORY` + DB-র `categories` টেবিল — দুটোই, আগে।

## সবসময়

- **commit, push, deploy, Supabase-এ লেখা — মালিকের অনুমতি ছাড়া না।** একবার অনুমতি মানে চিরকাল না।
- কাজ শেষে `npm run typecheck`, `npm run lint`, `npm run build` — তিনটাই পরিষ্কার না হলে কাজ অসম্পূর্ণ।
- যা যাচাই করা হয়নি, চুপচাপ বাদ দেবেন না — বার্তায় বা docs-এ লিখে রাখবেন।
- শেষে [adding-products.md](adding-products.md)-এর ধাপ আর ফিচার ফাইলের চেকলিস্ট/ট্র্যাকার আপডেট — এটাও কাজের অংশ, আলাদা কাজ নয়।
