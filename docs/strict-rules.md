# নিয়মাবলী ও নির্দেশিকা — পণ্য বা দোকান যোগের নির্দেশিকা

এই প্রজেক্টে পণ্য, অফার বা দোকান যোগ করার সময় ডেটার নির্ভুলতা ও স্থায়িত্ব বজায় রাখার জন্য এই নির্দেশিকা অনুসরণ করতে হবে। নিয়মগুলো বাস্তবসম্মত এবং কোনো গুরুত্বপূর্ণ দোকান বা পণ্যকে অযথা বাদ না দিয়ে কার্যকরভাবে অন্তর্ভুক্ত করার উদ্দেশ্যে তৈরি। ধাপে ধাপে কীভাবে করতে হয় তা [adding-products.md](adding-products.md)-এ বর্ণিত।

## পণ্য যোগের নিয়ম

1. **আসল দাম যাচাই করবে:** প্রতিটা দোকানের পাতায় ঢুকে লাইভ দাম, স্টক আর ছবি নিশ্চিত করবে। আন্দাজের দাম, অনুমানের তালিকা বা AI-জেনারেটেড কাল্পনিক দাম গ্রহণযোগ্য নয়।
2. **মডেল ও স্পেসিফিকেশনের সঠিক মিল:** একই নামে ভিন্ন মডেল বা ভিন্ন জেনারেশন হয় (যেমন Baseus Adaman 22.5W ≠ Adaman 2 30W; Bipow 15W ≠ Bipow 20W)। মডেল কোড (যেমন PPADM20S, OPB-7103C) থাকলে তা মিলিয়ে নেওয়া সর্বোত্তম। তবে যে দোকানে মডেল কোড সরাসরি পেজে লেখা থাকে না (যেমন স্কিনকেয়ার, ফ্যাশন, বা কিছু রিটেইলার), সেখানে পণ্যের নাম, মূল স্পেসিফিকেশন ও ভ্যারিয়েন্ট নিশ্চিত হলে অফার রাখা যাবে (অনিশ্চিত হলে রিভিউয়ে রাখা যাবে, কিন্তু অন্ধভাবে বাতিল করার দরকার নেই)।
3. **দোকানের সংখ্যা (বাস্তবসম্মত নিয়ম):** ক্যাটালগে যোগ করার জন্য পণ্যে অন্তত ৩টি দোকান থাকা আদর্শ ("প্রস্তাবিত")। তবে নতুন লঞ্চ হওয়া পণ্য, হাই-এন্ড ভ্যারিয়েন্ট বা ব্র্যান্ড-এক্সক্লুসিভ আইটেমের ক্ষেত্রে অন্তত **১-২টি বিশ্বস্ত দোকান** থাকলেই পণ্য যুক্ত করা যাবে। পরবর্তীতে সিস্টেমের ব্যাকগ্রাউন্ড অটোমেশন বা বিশেষ স্ক্রিপ্ট সময়ের সাথে সাথে বাকি দোকান খুঁজে সংযুক্ত করে নেবে। Stock out লিস্টিংও গণ্য হবে (`inStock: false` সহ)। শুধু দামহীন ("To be announced" / "Call for Price") পাতাকে অফার ধরা যাবে না।
4. **অফিসিয়াল দাম ও ভারসাম্য (Sanity Check):** অফিশিয়াল দাম থাকলে প্রতিটা ভার্সনে `officialPrice` দিতে হবে। তবে যে ব্র্যান্ড বা পণ্যের বাংলাদেশে অফিসিয়াল বিক্রি বা ঘোষিত MSRP নেই (যেমন Motorola, Google Pixel, ইমপোর্টেড আইটেম), তার `officialPrice` খালি (`null`) থাকবে অথবা বিশ্বস্ত রিটেইলারদের নিয়মিত/লিস্টেড দামের মিডিয়ান ধরা যাবে। অস্বাভাবিক ভুল লিস্টিং (যেমন কভার বা গ্লাস) ফিল্টার করতে আনুমানিক ৪০%-২৫০% ব্যান্ডের বাইরে গেলে সরাসরি ফেলে না দিয়ে অ্যাডমিন রিভিউতে পাঠাবে।
5. **নামের নিয়ম:** ব্র্যান্ড আলাদা ফিল্ডে। মডেলে Pro, Max, Plus, Ultra, FE, 5G, সাইজ, চিপ ইত্যাদি সুনির্দিষ্টভাবে রাখতে হবে, যাতে ভ্যারিয়েন্ট সঠিকভাবে শনাক্ত হয়।
6. **স্পেক্স আর ছবি:** `specsSource` হিসেবে Star Tech, অফিসিয়াল ব্র্যান্ড পেজ, GSMArena, বা যেকোনো নির্ভরযোগ্য রিটেইলারের স্পেসিফিকেশন টেবিলের লিংক দিন। ছবি আসল CDN URL থেকে সর্বোচ্চ ৫টি রাখা যাবে।
7. **Condition সততা:** দোকানের ধরন অনুযায়ী সঠিক condition নির্ধারণ করুন:
   - অফিসিয়াল ডিস্ট্রিবিউটর: `official`
   - গ্রে/ইমপোর্টেড মার্কেট: `unofficial`
   - ব্যবহৃত/ব্যবহৃত পণ্য: `used`
   - স্নিকার্স/পোশাক: আসল হলে `official`, উন্নত মানের রেপ্লিকা হলে `replica_premium`, সাধারণ হলে `replica`।
8. **একই পণ্য দুবার নয়:** ভিন্ন সাইজ বা স্টোরেজ (যেমন 128GB, 256GB, 40mm, 44mm) আলাদা পণ্য নয়, একই পণ্যের ভ্যারিয়েন্ট।
9. **`releaseYear`:** পণ্য ঘোষণার প্রথম বছর দিন।
10. **দেশের নাম সুনির্দিষ্ট:** JP, Japan, Japan Version স্বয়ংক্রিয়ভাবে "Japan"; International মানে "Global" (`src/utils/region.ts`)।
11. **যাচাই ও ট্র্যাকিং:** `npm run worker:check` চালিয়ে যাচাই করুন। কোনো অমিল থাকলে তা সংশোধন করুন বা অ্যাডমিন রিভিউ ফ্ল্যাগে রাখুন।
12. **ভ্যারিয়েন্টে ন্যূনতম ২ দোকান (২৯ অক্টোবর ২০২৬-এর মালিকের নিয়ম):** প্রতিটা ভ্যারিয়েন্টে অন্তত **২টি দোকানের published অফার** থাকবে; ১ দোকানের ভ্যারিয়েন্ট ক্যাটালগ থেকে বাদ যাবে (ভ্যারিয়েন্ট মুছলে অফারও cascade-এ মুছে যায়; পণ্যের *সব* ভ্যারিয়েন্ট বাদ পড়লে পুরো পণ্যই বাদ — সেক্ষেত্রে মালিকের অনুমতি নেবে)। একমাত্র ছাড়: **নতুন লঞ্চ পণ্য** (`releaseYear` = চলতি বছর) — ধাপ ৩-এর ১–২ বিশ্বস্ত দোকান সুবিধা, worker সময়ের সাথে বাকি দোকান জুড়ে নেয়। DB থেকে মুছলে [seed.sql](../supabase/seed.sql)-এর সংশ্লিষ্ট লাইনও মেলাতে হবে (id = `md5('variant:<slug>~v<N>')`), নইলে পরের seed run-এ ফিরে আসে বা FK error দেয়।

## দোকান (সেলার) যোগের নিয়ম

1. **কোনো দোকানই স্থায়ীভাবে বাদ নয় (No store is permanently banned):** কোনো দোকানকে কখনোই "স্থায়ীভাবে বর্জন" করা যাবে না। প্রতিটি গুরুত্বপূর্ণ দোকান আমাদের ক্রেতাদের জন্য মূল্যবান।
2. **লোকাল রানার:** GitHub Actions এর সার্ভারের IP আটকানো (403) অনেক দোকান ঘরের IP থেকে সৎ `DordamBot` পরিচয়ে ঠিকই খোলে। এগুলো ম্যাক/PC/ফোনের লোকাল রানার (`scripts/local-runner.sh`) থেকে পড়া হয়: জব `local_prices` (দাম) আর `local_discover` (নতুন পণ্য খোঁজা); দোকানের তালিকা `workers/stores/local.ts`। বিস্তারিত [local-runner.md](local-runner.md)।
3. **অনুরোধের পরিচয়:** সব অনুরোধ নিজের `DordamBot` পরিচয়ে, robots.txt মেনে, প্রতি হোস্টে ২টার বেশি একসাথে নয়। আটকালে (403, 429, bot challenge) সেই দোকান ওই run-এ বাদ।
4. **নিষ্ক্রিয় দোকান (স্থায়ী বর্জন নয়, `sellers.active = false`, `active = true` করলেই ফেরে):** যে দোকান সাধারণ worker বা লোকাল রানার কোনোটাতেই পড়া যায় না, বা আমাদের ক্যাটালগে মেলার মতো পণ্য নেই। ৪ নভেম্বর: Ryans, TechLand, Pickaboo, GadStyle, Ghorer Bazar, Naturo BD (সাধারণ অনুরোধে আটকানো); Hype Cave, Prime Nation (Shopify-র বট-নিয়ন্ত্রণে ৪২৯, ওদের UCP পথ বানানো হয়নি); Sundora, Zapatos (ক্যাটালগে মেলা পণ্য ০)। পথ পেলে (দোকানের allowlist বা প্রোডাক্ট ফিড) ফেরানো হবে। Chaldal ঘরের IP থেকেও সংযোগ হয় না।
   - **HNS Tech** (`hnstechbd.com`): সাধারণ worker-এর `hnstech` স্টোর, sitemap নেই বলে `/shop?page=1..6` ঘুরে listing; দাম পাতার `data-variants` JSON-এ (`hnstechVariants`)।
   *(মালিকের সিদ্ধান্ত অনুযায়ী বাদ: Daraz — থার্ড-পার্টি সেলারদের অবিশ্বস্ত ভ্যারিয়েন্ট/কপি পণ্যের কারণে; এবং Shwapno — গ্রোসারিকেন্দ্রিক হওয়ায় ক্যাটালগ থেকে বাদ)*
5. **workers/stores/index.ts এ এন্ট্রি:** যেসব দোকান সরাসরি HTTP-তে চলে সেগুলো `sitemapStore` হিসেবে থাকবে; আর যেসব দোকান শুধু GitHub-এর IP-তে আটকায় সেগুলো কনফিগে থেকে `workers/stores/local.ts`-এর তালিকায় যোগ হয়ে লোকাল রানারে পড়া হবে।

## ডেটা পাইপলাইন

```
data/catalog/<ক্যাটাগরি>.json  →  worker:check
→ catalog:specs  →  catalog:build
→ seed: npx supabase db query --linked -f supabase/seed.sql
→ build:data  →  npm run build
```

- নতুন দোকান পরীক্ষা: `npm run store:scan -- <ডোমেইন>` (robots, sitemap, পাতা পড়া যায় কি না)।
- ক্লাউড আইপি ব্লকিং থাকলে লোকাল রানার: `sh scripts/local-runner.sh` (অ্যাডমিন থেকে চালানো যায়)।

## নীতি ও স্বচ্ছতা

- ডেটাবেস ও প্রোডাকশনে লেখার আগে সর্বদা যাচাই ও প্রয়োজনীয় অনুমতি নিশ্চিত করুন।
- কাজ শেষে `npm run typecheck` এবং `npm run lint` পরিষ্কার রাখুন।
- যেকোনো নতুন দোকান বা পরিবর্তন সংক্রান্ত ডকুমেন্টেশন হালনাগাদ রাখুন।
